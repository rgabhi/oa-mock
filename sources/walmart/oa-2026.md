### 1. Circular queue of primes

Given positive integers N and P, form a circular queue of all primes up to N. Keep summing along the queue and find the first index (0-based) where the sum becomes strictly greater than P. Example: N = 20, P = 25: queue 2, 3, 5, 7, 11, 13, 17, 19; 2+3+5+7+11 = 28 > 25, so the answer is the index of 11, which is 4.

→ `data/walmart/questions/primeloop.json` (*Circular Queue of Primes*). No constraints were reported. Assumed: the queue wraps round when P is larger than the sum of all the primes, and the answer is the index within the list of primes (not the number of steps taken). The mock uses 2 ≤ N ≤ 10⁶ and 1 ≤ P ≤ 10¹⁵ (P is capped so it is exact in JavaScript).

## Walmart OA, IIT BHU

### 1. Minimum relay packs

A shuttle goes forward from 0 to L and starts with range S. M relay stations are given as [position, battery contribution], sorted by position. A pack can be collected only after reaching its station, each at most once, and collecting never reduces the range. Return the minimum number of packs needed to reach L, or -1. Constraints: 1 ≤ L ≤ 10⁹, 0 ≤ M.size() ≤ 2·10⁵, 0 ≤ position < L, 1 ≤ contribution ≤ 10⁹, 0 ≤ S ≤ 10⁹, use 64-bit arithmetic. Signature: `int minRelayPacks(int L, vector<vector<int>>& M, int S)`. Suggested method: greedy with a max-heap. No examples were given.

→ `data/walmart/questions/relaypacks.json` (*Minimum Relay Packs*). Samples are our own. Assumed: the shuttle succeeds when its range is at least L; a station at exactly the current range can be reached.

### 2. Count valid advertisement schedules

n slots, c campaigns, the same campaign may appear in at most k consecutive slots. Count schedules modulo 10⁹+7. Constraints: 1 ≤ n ≤ 10⁹, 1 ≤ k ≤ 100, 1 ≤ c ≤ 10⁹. Signature: `int fun(long long n, int k, long long c)`. Samples: (n=3, k=2, c=2) gives 6; (n=4, k=2, c=2) gives 10. Suggested method: DP with matrix exponentiation.

→ `data/walmart/questions/adschedules.json` (*Count Valid Advertisement Schedules*).

### 3. Maximum benefit with two assistants

N tasks, benefit1[i] if assistant A1 does task i, benefit2[i] if A2 does it. A1 does exactly K tasks and A2 does the rest. Return the maximum total benefit. Constraints: 1 ≤ N ≤ 10⁵, 0 ≤ K ≤ N, 1 ≤ benefit ≤ 1000. Signature: `int maxBen(vector<int>& benefit1, vector<int>& benefit2, int k)`. Samples: N=3, K=2, [10,20,30] and [5,25,15] gives 65; N=4, K=4, [15,25,35,45] and [5,10,20,30] gives 120. Suggested method: greedy and sorting.

→ `data/walmart/questions/twoassist.json` (*Split Tasks Between Two Assistants*). The mock's function takes `k` first, so the input is `n k` then the two arrays.

### 4. Assigning modules to three servers

M modules with integer difficulties d_i and 3 servers. Every module goes to one server and each server gets at least one. For an assignment, compute the minimum of |d1 - d2| + |d2 - d3| over choices of d_i from the modules on server i. Find the maximum of these minimums over all assignments.

The same statement was forwarded three times, and reported again from IIT Madras ("this question got repeated today", the first coding problem) and IIT Kharagpur ("this ques got repeated"). It is Codeforces 1740C (*Bricks and Bags*) with modules and servers in place of bricks and bags, which gives the constraints (3 ≤ n ≤ 2·10⁵, 1 ≤ a_i ≤ 10⁹).

→ `data/walmart/questions/threeservers.json` (*Assign Modules to Three Servers*), listed under IIT Madras. The tests were made with our own solution, checked against a brute force over every assignment.

### 5. Backend task: Finance Transaction Analytics API

Node.js and Express. A list of transaction objects (`transactionId`, `userId`, `city`, `type` DEBIT or CREDIT, `amount`) is already in memory. Three endpoints:

- `GET /transactions/location/:city`: total debit and total credit in that city, as `{ "totalDebit": ..., "totalCredit": ... }`.
- `GET /transaction/:id/location/:city`: the same totals for one user in one city.
- `POST /transactions/location/:city`: an array with one `{ userId, totalDebit, totalCredit }` per user in the city; the response is also saved to a JSON file on the server. (It needs no request body but is a POST in the task.)

Each returns 404 with "the exact error message provided in the original assessment" when nothing matches. That message was not shared. Example dataset: transactions 101 to 104 (Ahmedabad: user 1 debit 500, user 2 credit 1000, user 1 credit 200; Mumbai: user 3 debit 700), giving `{ "totalDebit": 500, "totalCredit": 1200 }` for Ahmedabad.

The DOCX adds: the response shapes, the example dataset with its totals, that API 3's array has `userId`, `totalDebit`, `totalCredit` per user, that its response is saved to a JSON file, and that all three return 200 on success and 404 when nothing matches. IIT Madras reported the same task as its second coding problem ("select one of Node.js / Python / Spring Boot and write 3 APIs": sums by city, by user ID and city, and a third the candidate didn't remember).

→ `data/walmart/repos/finance-analytics/` (*Finance Transaction Analytics API*, a repository question in Node.js, Django and Spring Boot). Not reported, so the mock's own: the 404 body (`{"message": "No transactions found"}`), the file (`output/{city}.json`), sorting the summary by `userId`, exact city matching, and more transactions in the dataset (the reported four are kept, so the example totals still hold).

## Walmart OA, IIT Guwahati (2026)

### 1. Maximum peaks with minimum cost

Array t of n integers. An index is a peak if t[i-1] < t[i] > t[i+1]; the first and last can never be peaks. One operation adds a positive value to any element. Make the maximum possible number of peaks with the minimum total value added, and return that total. Example: `5 1 2 3 4 5` (n = 6) gives 4 (add 2 at index 2 and 2 at index 4). Typical constraints: 3 ≤ n ≤ 10⁵, 1 ≤ t[i] ≤ 10⁹. The note's hint was a House-Robber style DP over cost[i] = max(0, max(t[i-1], t[i+1]) + 1 - t[i]).

→ `data/walmart/questions/peaks.json` (*Maximum Peaks at Minimum Cost*). The maximum number of peaks is (n-1)/2, so the reference picks exactly that many non-adjacent indices. For odd n that forces indices 1, 3, 5, ...; for even n it is a prefix of odd indices followed by a suffix of even ones.
